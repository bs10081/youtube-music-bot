# Folia 上游升級計劃：v0.5.22 → v0.7.20（2026-10-16）

## 背景與可行性判定

我們的 `folia-web` 映像由 `deploy/folia/Dockerfile` 從上游 `chthollyphile/folia-major`
pin commit 建置，外加兩個 patch（AGPL-3.0 合規：修改原始碼公開於 repo）。

| 項目 | 現況 | 上游最新 |
|---|---|---|
| Pin | v0.5.22（`7d05426738837890005180cd74b503ce5400ede9`，2026-07-05） | v0.7.20（`1b39fd868e2ddda95788f1baa839c032f3e7a285`，2026-10-15） |
| 差距 | — | 1684 commits |
| Node 需求 | Dockerfile 用 node:20-slim | 上游 engines 要求 **Node ≥ 24** |

**判定：可行。** 已對 v0.7.20 實際試套兩個 patch（`git apply --check` 全失敗），
因此必須重生補丁；WS 協定相容，bot 端 `src/websocket/folia-bridge.ts` 不用改。

## 已驗證的關鍵事實

1. **Patch 1**（origin 推導端點）：
   - `src/services/nowPlayingProvider.ts`：`NOW_PLAYING_WS_URL = 'ws://localhost:9863/api/ws/lyric'` 仍在（第 3 行），上下文漂移 → 補丁要重生成。
   - `src/utils/nowPlayingClock.ts`：`NOW_PLAYING_PROGRESS_QUERY_URL = 'http://localhost:9863/api/query/progress'` 仍寫死（第 5 行）→ 仍需改為 `/api/query/progress`。
   - 上游新增 OBS 來源頁 `?host=` 參數（`parseObsWebParams`），但 `buildNowPlayingWsUrl` 寫死 `ws://` 前綴，在 `https://lyrics.moli.rocks` 會被 mixed-content 擋 → **不能取代 patch 1**。
2. **Patch 2**（`enableNowPlayingStage` 預設開啟）：`useSettingsUiStore.ts` 已被上游拆分；設定搬到 `src/stores/useStageSettingsStore.ts`（第 74 行，預設仍 false）→ 補丁改目標檔。
3. **協定相容**：v0.7.20 provider 處理事件 `Track` / `Lyric` / `PlayerPauseState` / `PlayerProgress` / `PlayerProgressReplay`，與 bot bridge 的發送事件完全一致；duration 秒/毫秒自動判別邏輯仍在。
4. **建置產物**：v0.7.20 仍有 `LICENSE` 與 `api-ts/tsconfig.json`（`npm run build` = `build:vercel-api` + `vite build` 不斷）；vite 預設 `dist/` 輸出，nginx 掛載方式不變。
5. **CI**：`.github/workflows/folia-image.yml` 會斷言 `FOLIA_COMMIT` 檔與 Dockerfile `ARG` 預設一致 → 兩處都要改。

## 決策（君已於 2026-10-16 全部同意）

- 一次跳 v0.7.20，不走中繼版本。
- 維持 pin＋patch 模式，不 fork。
- 歌詞頁入口維持主 app（`index.html`）＋ patch 2；OBS 來源頁列為後續評估。
- Dockerfile `node:20-slim` → `node:24-slim`。
- 受控部署：先 pin digest、關 watchtower label、驗證通過後再放回 watchtower。
- 驗收三項：CI 建置（amd64+arm64）、Pi 上 WS probe 端到端、瀏覽器實測歌詞滾動。
